# Frontend Refactoring Design: Connect transport, Next.js 16, feature folders

Status: Implemented on branch `refactor/connect-next16` (2026-10-29). Specs: `docs/specs/01..04`.
Inputs: AST graphs and structure docs in
`docs/research/playground-frontend/analyses/` (outside this repo), the shared contract
`playground-proto` (`README.md`, `docs/SECURITY_PROTOCOL.md`, `docs/RPC_DESIGN.md`,
`proto/playground/api/v1/*.proto`).

Scope: platform upgrade, transport migration and structural refactoring with behaviour preserved.
Visual redesign is explicitly out of scope (a separate UI/UX pass follows).

---

## 1. Why

The backend is moving to one public edge: the Connect protocol, binary protobuf, cookie sessions,
Origin allow-list and the `Connect-Protocol-Version` header, with no REST, WebSocket, SSE or CSRF
endpoint (`SECURITY_PROTOCOL.md` section 2, L2). The frontend currently speaks four transports, and
three of them will stop existing. At the same time the platform is end-of-life: Next.js 14.2.5,
React 18, Node 18 (EOL), `next-pwa` (unmaintained, webpack only), ESLint 8, Tailwind 3.

## 2. Current structure (before)

Numbers come from `graph/file-graph.json` and `01-code-graph.md`.

### 2.1 Transport quadruplication

| Transport | Files | LOC | Reached from UI |
|---|---|---|---|
| axios REST + CSRF | `src/lib/api.ts`, `src/lib/csrf.ts` | 332 | yes (fan-in 21) |
| Zod REST client | `src/lib/api-client.ts`, `src/lib/schemas/*`, `src/lib/types/result.ts`, `src/lib/errors/api-error.ts` | ~1,230 | no (fan-in 0) |
| gRPC-Web (two implementations) | `src/lib/grpc-client.ts`, `src/lib/grpc/**` | 1,462 | no; generated code is gitignored, so it cannot even compile |
| WebSocket | `src/lib/websocket/*`, `src/hooks/useWebSocket.ts` | 624 | yes, when settings `execution_mode = websocket` |
| SSE | `src/lib/sse-client.ts`, `src/hooks/useSSE.ts` | 410 | no UI caller |

Each path had its own validation and auth story. `src/lib/grpc/clients/config.ts` read a JWT
from `localStorage` while REST used httpOnly cookies + CSRF; the WebSocket opened without auth
(`src/lib/websocket/client.ts:69`). `proto/` was a stale copy of backend protos (missing
`FormatCode`), regenerated by `scripts/generate-proto.sh` with `grpc-tools` + `ts-protoc-gen`.

### 2.2 `src/lib/api.ts` is a hub that couples types to transport

`api.ts` exports both the axios instance and every domain type (`Language`, `ExecuteResponse`,
`Share`, `EditorSettings`, ...). 21 files import it, most for types only
(`src/lib/history.ts`, `src/lib/utils/language.ts`, components). Any transport change ripples into
leaf utilities.

### 2.3 Duplicated domain types

`ExecuteRequest` existed four times (snake_case in `api.ts`, camelCase in `grpc/clients/execution.ts`,
Zod-inferred in `schemas/execution.schema.ts`, and `websocket/protocol.ts`). `Result<T,E>` existed
twice (`lib/result.ts`, `lib/types/result.ts`).

### 2.4 Hook fan-out in the page

`src/app/[locale]/page.tsx` has fan-out 17 (10 hooks, 4 components, 2 lib modules, 1 context), 7
modal `useState`s and 12 `useKeyboardShortcut` calls. Hooks import transport modules directly.

### 2.5 Platform defects found during analysis

* `src/i18n.ts` used the `locale` argument of `getRequestConfig`, removed in next-intl 4 (it must
  await `requestLocale`).
* Production CSP had no nonce and no `'unsafe-inline'` for scripts, so App Router inline bootstrap
  scripts were blocked unless another header overrode it; `'unsafe-eval'` was allowed everywhere.
* `X-Frame-Options: DENY` + `frame-ancestors 'none'` applied to `/embed/*`, which defeats the embed
  feature whose only purpose is to be framed.
* `X-XSS-Protection` is deprecated and can introduce XS-Leaks.
* `src/app/[locale]/web-vitals.ts`, `src/hooks/useLocalStorage.ts`, `src/components/LanguageToggle.tsx`
  have no importer.
* E2E specs target routes that do not exist (`/auth/login`, `/share/:id`).

## 3. Target structure (after)

```
src/
  app/                         routes only (layouts, pages); no data access
  proxy.ts                     next-intl routing + per-request CSP nonce (was middleware.ts)
  i18n/{routing,request}.ts    next-intl 4 configuration
  lib/rpc/                     the only network layer
    transport.ts               createConnectTransport (binary, credentials: include, timeouts)
    clients.ts                 typed clients for the 5 public services; injectable transport
    errors.ts                  ConnectError + ErrorDetail -> RpcFailure (kind, message, retryAfter)
    validate.ts                protovalidate + checkTotalSource before sending
    run-stream.ts              Run stream accumulator + session (seq/gap, UTF-8 decoding, reconnect);
                               also defines the ExecutionResult view model
    context.tsx                RpcProvider (tests inject createRouterTransport fakes)
  features/
    editor/                    CodeEditor, FileTabs, FileTree, LanguageSelector, TemplateGallery,
                               SnippetLibrary, useFiles, useLanguages, useSnippets, monaco/
    execution/                 useCodeExecution, OutputPanel, HistorySidebar, useHistory, history store
    share/                     useShare, ShareModal, loadShare (embed)
    auth/                      AuthProvider/useAuth (GetSession), AuthModal
    settings/                  useSettings (Get/UpdateSettings), SettingsModal, useTheme, useLayout
  components/ui, components/*  feature-neutral UI (buttons, Toast, ErrorBoundary, ShortcutsHelp)
  hooks/                       feature-neutral hooks (useToast, useKeyboardShortcut, useButtonHover)
  lib/                         feature-neutral utilities (csp, security/sanitize, ansi-parser, utils)
```

Dependency rule: `app -> features -> {components, hooks, lib}`; `features/* -> lib/rpc`; only
`lib/rpc` imports `@connectrpc/*`; generated types come from `@kingsejong-lang/playground-proto`.
Features import each other's files directly for now (`share` uses `editor/templates.ts`); per-feature
`index.ts` public files are deferred to the UI pass because components are still being reshaped.

Domain types are the generated protobuf types. View models that the UI needs and the protocol does
not define live in the owning feature, except `ExecutionResult`, which is produced by
`lib/rpc/run-stream.ts` and therefore defined there (so `lib` never imports `features`).

Zod remains only where protovalidate does not apply: values read back from `localStorage`
(history, snippets) and imported history/snippet files. It is imported through `src/lib/zod.ts`
(`jitless`, CSP-safe).

## 4. Decisions

Each decision lists the chosen option first, then at most two alternatives.

### D1 Single transport: Connect (connect-es v2) from the browser

Chosen because it is the only protocol the gateway exposes. Binary codec (`useBinaryFormat: true`),
`credentials: "include"` so the `__Host-pg_*` cookies flow, default timeout 15 s for unary calls,
none for `Run` (bounded by the server). Requires `NEXT_PUBLIC_API_URL` to be the gateway origin.

* Alt A: Next.js BFF (route handlers call the gateway server-side). Removes CORS and hides the
  gateway, but every stream is proxied twice and the Node tier becomes stateful. Rejected in the
  contract (`SECURITY_PROTOCOL.md` section 2).
* Alt B: Connect JSON codec in development. Easier to read in DevTools, but the gateway accepts
  only `application/proto`; would need a server flag. Not adopted.

### D2 Run stream semantics in one place (`lib/rpc/run-stream.ts`)

A pure reducer consumes `RunEvent`s and produces `ExecutionResult`: status, per-stream text decoded
with one `TextDecoder("utf-8", {stream: true})` per stream, diagnostics, truncation, metrics, and
`gaps` (number of missing `seq` values). The hook wraps it with an `AbortController`
(`cancel()` aborts the fetch, which the server treats as cancellation). If the stream fails after
`Accepted` with `Unavailable`/`Unknown`/`DeadlineExceeded` (dropped connection), the session polls
`GetExecution` with backoff (1 s, 2 s, 4 s, max 5 tries) until a terminal status, marking the
result `reconnected` (output is not replayed by contract). `Cancel` RPC is used when the user
cancels while only the poll is active (no stream to abort).

* Alt A: auto-retry `Run` with the same `client_request_id`. Idempotency returns the existing run but
  the contract does not replay output, so the user would see a blank result; polling is cheaper.
* Alt B: keep per-event React state (`streamEvents[]` like before). Simpler, but re-renders on every
  chunk and leaves decoding/ordering logic in components.

### D3 Client-side validation before sending

`validate.ts` runs `createValidator()` from `@bufbuild/protovalidate` on the request message and
`checkTotalSource()` from `@kingsejong-lang/playground-proto/limits`. Violations become an
`RpcFailure` of kind `validation` with the field path, so the UI shows the same message as a server
`REASON_VALIDATION`. The gateway remains authoritative.

* Alt A: hand-written Zod mirrors of the proto rules. Duplicates rules and drifts (the old
  `schemas/*` already disagreed with the backend).
* Alt B: no client validation. Smaller bundle (~protovalidate + CEL), worse feedback, one more
  round trip per typo.

### D4 Error mapping from Connect codes and `ErrorDetail`

`toRpcFailure(err)` uses `ConnectError.from(err)` and `findDetails(ErrorDetailSchema)`. Mapping by
`reason` first, then code. `retry_after_seconds` is surfaced as `retryAfterSeconds` and in the
message ("Try again in N s"). Network failure (`fetch` rejects) maps to kind `unavailable` with
"The playground server is unavailable"; this is the graceful backend-absent state.

### D5 Next.js 16 + React 19 + Turbopack

Codemods: `next-async-request-api` (layout `params`), manual `middleware.ts -> proxy.ts`
(`middleware-to-proxy` found nothing to rewrite because the file uses a default export of
`createMiddleware`). `swcMinify`, `modularizeImports` (for a test library) and the
`@testing-library/react` entry of `optimizePackageImports` removed. `next lint` replaced by the
ESLint CLI with flat config (`eslint.config.mjs`, `eslint-config-next/core-web-vitals` +
`/typescript`). `images` keeps explicit `formats`/`minimumCacheTTL` (no `next/image` usage today).

### D6 TypeScript 6.0.3 instead of 7.0.2

TypeScript 7.0.2's npm package exports only `./lib/version.cjs` plus `unstable/*` APIs (no classic
compiler API), and `typescript-eslint@8.72.1` (pulled by `eslint-config-next@16.4.3`) declares
`peerDependencies.typescript: ">=4.8.4 <6.1.0"`. Next's build-time type check also loads the
`typescript` JS API. Using 7 would disable type-aware linting and the build type check, so 6.0.3 is
pinned. Revisit when typescript-eslint supports 7.

* Alt A: TS 7 for `tsc --noEmit` via `@typescript/native-preview` side by side with TS 6 for tooling.
  Faster checks, two compilers to keep in sync. Not adopted now.

### D7 Unit tests: Vitest 5 instead of Jest 30

`@kingsejong-lang/playground-proto` is ESM-only (`"type": "module"`), as are parts of connect-es and
protovalidate. Jest needs `transformIgnorePatterns` + Babel/SWC for every ESM dependency and
`next/jest` loads the full Next config. Vitest runs ESM natively, matches the proto package's own
test runner, and `vi` is API-compatible with `jest` for the existing tests.

* Alt A: Jest 30 with `next/jest` and ESM transform allow-list. No test rewrite, but slower and the
  allow-list must track transitive ESM packages.

### D8 PWA: remove the service worker, keep the manifest

`next-pwa` is unmaintained and webpack-only; Next 16 builds with Turbopack. `@serwist/next` 9 is
also a webpack plugin. The app is useless offline (every action calls the backend), and a caching
service worker serving stale HTML conflicts with per-request CSP nonces. `public/manifest.json`
stays and is linked from metadata.

* Alt A: `@serwist/next` with `next build --webpack`. Keeps offline shell, gives up Turbopack builds.
* Alt B: `@serwist/turbopack` / `serwist` CLI `injectManifest` after `next build`. Keeps Turbopack;
  extra build step and SW cache invalidation to maintain.

### D9 Tailwind 4 via `@tailwindcss/upgrade`

The tool migrated `tailwind.config.ts` into CSS (`@import 'tailwindcss'`, `@theme`,
`@custom-variant dark`), renamed v3 utilities in 14 files and replaced `autoprefixer` with
`@tailwindcss/postcss`. Design tokens are CSS custom properties in `src/app/globals.css`.

### D10 CSP: per-request nonce from `proxy.ts`

`script-src 'self' 'nonce-<n>' 'strict-dynamic'` (+ `'unsafe-eval'` only in `next dev`, required
by React dev tooling). `'strict-dynamic'` lets the nonce'd Monaco loader inject the CDN scripts it
needs, so the CDN host is not listed in `script-src`. Pages render dynamically (the layout awaits
`headers()`); static HTML could not carry a fresh nonce. `connect-src 'self' <API origin>` (+ Monaco CDN
for source maps, + `ws:` HMR in dev). `style-src 'self' 'unsafe-inline' cdn` stays: Monaco and
React `style` attributes inject inline styles (documented residual). `/embed/*` gets
`frame-ancestors *` and no `X-Frame-Options`; all other routes `frame-ancestors 'none'` + `DENY`.
`X-XSS-Protection` removed.

* Alt A: static CSP in `next.config` headers with `'unsafe-inline'` scripts. Keeps static
  rendering possible, but allows any injected inline script.
* Alt B: self-host Monaco (`monaco-editor` npm + `loader.config({ monaco })`). Removes the CDN from
  CSP entirely; adds ~4 MB to the bundle and worker configuration under Turbopack.

## 5. Behaviour mapping (old -> new)

| Behaviour | Before | After |
|---|---|---|
| Load languages | `GET /languages` | `LanguageService.ListLanguages`; default `kingsejong` (falls back to legacy `kingsejong_v0_3`, then the first) |
| Run | REST `POST /execute` or WebSocket (setting) | `ExecutionService.Run` stream only; the "Execution Mode" setting is removed |
| Run payload | active file only, named `main<ext>` | same: active file only, named `Language.default_entry_file` or `main<ext>`. Multi-file runs are a product decision left open |
| Format | `POST /languages/:id/format` | `LanguageService.FormatCode`; diagnostics shown as an error toast |
| Templates | hard-coded catalogue + `GET template` | `ListTemplates` + `GetTemplate` (server is source of truth) |
| Share create/load/embed | REST | `ShareService.CreateShare/GetShare`; anonymous `delete_token` is kept in memory only (no delete UI existed) |
| Settings | REST, signed-in only | `SettingsService.Get/UpdateSettings` (field mask), signed-in only; `color_scheme` stays local (not in the contract) |
| Auth | REST + CSRF, `GET /auth/me` | `AuthService.Login/Register/Logout/GetSession`; cookies only; no CSRF |
| History | localStorage `ExecuteResponse` | localStorage `ExecutionResult`; legacy entries are converted on read (Zod) |
| Backend absent | spinner, then error text, plus `console.error` from hooks | spinner, then "The playground server is unavailable" in the output panel; no application-level console errors |

## 6. Migration steps (each step builds and tests green)

1. Runtime upgrade (spec 01): Node 26 pin, dependencies, Next 16 config, proxy.ts, next-intl 4,
   Tailwind 4, ESLint flat config, Vitest. Old transports still compile.
2. RPC layer (spec 02): add `lib/rpc/*` with tests against `createRouterTransport` fakes.
3. Switch hooks to `lib/rpc` one feature at a time (languages, execution, share, settings, auth),
   then delete axios/WS/SSE/gRPC/CSRF/schemas/`proto/`.
4. Feature folders (spec 03): move files with `git mv`, fix imports, keep re-export-free public files.
5. Security hardening (spec 04): CSP nonce, headers, embed framing, text rendering of share titles.
6. README and verification (audit, build, lint, typecheck, tests, dev smoke in a browser).

## 7. Risks and open items

* Two pre-existing defects fixed on the way because they blocked verification: Monaco themes and the
  KingSejong language were registered in `onMount` (first render used Monaco's light theme and plain
  text); they are now registered in `beforeMount`. Tailwind 3 `bg-opacity-50` overlays (not
  converted by the upgrade tool) were rewritten to `bg-black/50`.
* The Run button becomes a Stop button while a run is active (needed for R2.5); this is the only
  intentional visible change besides the removed "Execution Mode" setting.

* The contract has no endpoint to list a user's shares or delete UI; `delete_token` handling for
  anonymous shares is deferred to the UI pass.
* `style-src 'unsafe-inline'` remains (Monaco).
* Monaco is still loaded from jsDelivr at runtime (`@monaco-editor/loader` default version); the
  npm `monaco-editor` peer is installed only to satisfy the peer range.
* Without a running gateway, Connect behaviour was verified only against in-process
  `createRouterTransport` fakes, not against connect-go.
